# Express message variants with unions.

<p className="docs-summary">MyServiceBus&apos;s experimental .NET 11 support lets C# and Raven applications use standard union semantics for multi-message consumers and request responses. C# remains the primary .NET API; Raven shows how the same runtime contract can become especially concise when the language understands unions directly.</p>

<div className="callout callout-accent">
  <strong>Available in the core NuGet packages</strong>
  <p><code>Sundstrom.MyServiceBus</code> and <code>Sundstrom.MyServiceBus.Abstractions</code> include both <code>net10.0</code> and experimental <code>net11.0</code> assets. Use a .NET 11 preview SDK and target <code>net11.0</code> to activate this API. Preview runtime and language behavior may still change before .NET 11 is stable.</p>
</div>

## Keep the message contracts ordinary

Union support does not create a new wire-level message. Define concrete contracts as usual; the union is a local way to describe which of them a consumer or response can contain.

## Handle several message types with a custom C# union

The custom <code>OrderCommand</code> union expands into one topology registration for each case. A sent <code>SubmitOrder</code> is still identified and serialized as <code>SubmitOrder</code>; MyServiceBus constructs the union carrier only when invoking the consumer method.

<CodeViewer code={csharpConsumer} label="Union-typed C# consumer" language="csharp" />

This is an alternative to separate consumer methods or an inheritance hierarchy. Those existing styles remain supported and may be clearer when the cases do not belong together.

## Model request outcomes as variants

<code>Response&lt;T1, T2&gt;</code> implements the .NET union ABI and has a constructor for each response case. That enables implicit case conversion, exhaustive pattern matching, and non-boxing <code>TryGetValue</code> access while retaining the MyServiceBus response API.

## Raven makes the same model feel native

<a href="https://marinasundstrom.github.io/raven/">Raven</a> is a preview .NET programming language that compiles to CLR assemblies and is designed to express modern .NET features with concise syntax. It can reference the same NuGet packages, types, and runtime contracts as a C# application. Raven&apos;s syntax and behavior may change while it remains in preview.

Raven writes <code>System.Union&lt;SubmitOrder, CancelOrder&gt;</code> as <code>SubmitOrder | CancelOrder</code>. MyServiceBus recognizes the shared union ABI, so no Raven-specific adapter or base message type is required. This is where the .NET 11 work particularly complements Raven: the bus provides topology and dispatch semantics while the language provides concise variants and matching.

Raven also supports top-level (namespace-level) functions. A consumer method can therefore be an attributed function directly, as in the example below, without introducing a static container class solely to host the handler.

## Preserve cross-language exchange

The union carrier never becomes the interoperable contract. Java and other clients continue to publish and consume <code>SubmitOrder</code> and <code>CancelOrder</code> independently. They do not need union syntax, the .NET ABI, or knowledge that a C# or Raven endpoint groups those messages in one handler.

## Understand today&apos;s experimental boundary

<ul>
  <li>Consumer discovery currently recognizes the standard union ABI through cached reflection.</li>
  <li>Generated registration can describe the same expanded cases later for trimming, AOT, and faster startup.</li>
  <li>A typed <code>ConsumeContext&lt;TUnion&gt;</code> parameter is not supported yet; consume the union value directly.</li>
  <li>JSON writes the active case shape. Reading an object-shaped union requires an explicit classifier or discriminator policy.</li>
  <li>The concrete case types—not the union carrier—control topology names and wire compatibility.</li>
</ul>
