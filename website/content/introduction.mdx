# MyServiceBus at a glance.

<p className="docs-summary">MyServiceBus is a pre-1.0 asynchronous messaging runtime with aligned C# and Java APIs. It provides RabbitMQ-backed messaging, preview Azure Service Bus and Amazon SQS/SNS transports, and an in-process mediator built around MassTransit-familiar concepts.</p>

<div className="callout callout-accent">
  <strong>Current scope</strong>
  <p>RabbitMQ is the verified broker profile. Azure Service Bus and Amazon SQS/SNS are preview profiles with explicitly documented verification boundaries. MyServiceBus is not a drop-in replacement for every MassTransit feature; first-class orchestration—including sagas—and choreography lifecycle tooling remain future areas.</p>
</div>

<h2 id="why">Decision snapshot</h2>

<div className="docs-feature-grid">
  <div><span>01</span><h3>Primary fit</h3><p>C# and Java services that need corresponding message contracts, consumer semantics, and failure behavior.</p></div>
  <div><span>02</span><h3>Broker baseline</h3><p>RabbitMQ is the most established profile; Azure Service Bus and Amazon SQS/SNS retain preview boundaries.</p></div>
  <div><span>03</span><h3>Local dispatch</h3><p>The mediator supports commands, queries, notifications, handlers, and generated dispatch without a broker.</p></div>
  <div><span>04</span><h3>Compatibility</h3><p>MassTransit interoperability is pinned to named versions, transports, and tested message flows.</p></div>
  <div><span>05</span><h3>Maturity</h3><p>APIs can change before 1.0, and production promotion remains capability-specific rather than project-wide.</p></div>
  <div><span>06</span><h3>License and support</h3><p>The core is MIT-licensed; there is no equivalent of MassTransit&apos;s commercial support relationship today.</p></div>
</div>

<h2 id="same-concept">The same concept, idiomatic code</h2>

The APIs do not try to look identical. They preserve the same behavior while following each platform’s conventions for dependency injection, asynchronous work, and type systems.
